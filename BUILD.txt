The mipsel_24kc packages are built with the ramips/mt76x8 SDK, the
mipsel_74kc packages with bcm47xx/mips74k and the mips_24kc packages
with ath79/generic. The aarch64_generic packages are built with the
armsr/armv8 SDK, aarch64_cortex-a53 with mediatek/filogic,
aarch64_cortex-a72 with mvebu/cortexa72 and aarch64_cortex-a76 with
bcm27xx/bcm2712, x86_64 with x86/64 and riscv64_generic with
sifiveu/generic. The remaining package architectures use the SDKs listed
for their target in the table above (bmips/bcm6328, octeon/generic,
kirkwood/generic, gemini/generic, bcm53xx/generic, imx/cortexa9 and
mvebu/cortexa9). arm_cortex-a8_vfpv3 is built with omap/generic,
arm_cortex-a7_vfpv4 with at91/sama7, arm_cortex-a7_neon-vfpv4 with
ipq40xx/generic, arm_cortex-a7 with mediatek/mt7629 and
arm_cortex-a15_neon-vfpv4 with ipq806x/generic. All packages use musl.
The soft-float targets are mips_mips32, mips64_octeonplus and
arm_cortex-a7; the other ARMv7 targets are hard-float.

The prebuilt Rust binaries are generic aarch64 and are shared by all four
aarch64 package architectures; the mipsel Rust binaries are shared by
mipsel_24kc and mipsel_74kc. Every other package architecture has its
own Rust binaries, because the CPU, FPU and float ABI differ:
  mips_mips32             MIPS32 (r1), big-endian, soft-float
  mips64_octeonplus       MIPS64r2/Octeon+, n64 ABI, soft-float
  arm_xscale              ARMv5TE, soft-float
  arm_fa526               ARMv4T, soft-float
  arm_cortex-a9           ARMv7-A, soft-float, no NEON
  arm_cortex-a9_neon      ARMv7-A, hard-float, VFPv3-D16 + NEON
  arm_cortex-a9_vfpv3-d16 ARMv7-A, hard-float, VFPv3-D16
  x86_64, riscv64_generic own trees

RISC-V packages are built for 25.12.6 only. The 24.10.5 feeds have no
LuaJIT for RISC-V (HAS_LUAJIT_ARCH is not set and the package
architecture of sifiveu/generic is riscv64_riscv64), so zapret2 cannot be
built or installed there.

The packages can be installed on other targets with the same package
architecture as long as the target feed provides the required kernel
modules:
  kmod-nft-queue, kmod-nfnetlink-queue, kmod-nf-conntrack

Build the Rust binaries for mipsel_24kc / 24.10.5:
  SDK=/path/to/openwrt-sdk-24.10.5-ramips-mt76x8_gcc-13.3.0_musl.Linux-x86_64
  TC=$SDK/staging_dir/toolchain-mipsel_24kc_gcc-13.3.0_musl
  export PATH="$TC/bin:$PATH"
  export STAGING_DIR="$SDK/staging_dir"
  export CC_mipsel_unknown_linux_musl="$TC/bin/mipsel-openwrt-linux-musl-gcc"
  export CARGO_TARGET_MIPSEL_UNKNOWN_LINUX_MUSL_LINKER="$TC/bin/mipsel-openwrt-linux-musl-gcc"
  export RUSTFLAGS="-C target-feature=-crt-static"
  cd rust
  cargo +nightly build --release --target mipsel-unknown-linux-musl \
    -Z build-std=std,panic_abort --target-dir target-mipsel

Build the Rust binaries for the remaining ARM and MIPS package
architectures (shown for 24.10.5; use the matching 25.12.6 SDK and a
target-*-25.12 directory for 25.12.6). Select the target and extra flags
from this table:

  package arch              rust target                        extra flags
  mips_mips32               mips-unknown-linux-musl            -C target-cpu=mips32 -C target-feature=-mips32r2 -C link-arg=-mips32
  mips64_octeonplus         mips64-openwrt-linux-musl          -C link-arg=-march=octeon+ -C link-arg=-mabi=64
  arm_xscale                armv5te-unknown-linux-musleabi     none
  arm_fa526                 armv4t-unknown-linux-musleabi      custom target spec, see below
  arm_cortex-a9             armv7-unknown-linux-musleabi       none
  arm_cortex-a9_vfpv3-d16   armv7-unknown-linux-musleabihf     none
  arm_cortex-a9_neon        armv7-unknown-linux-musleabihf     -C target-feature=+neon
  arm_cortex-a8_vfpv3       armv7-unknown-linux-musleabihf     -C target-cpu=cortex-a8 -C target-feature=+vfp3,-neon
  arm_cortex-a7_vfpv4       armv7-unknown-linux-musleabihf     -C target-cpu=cortex-a7 -C target-feature=+vfp4,-neon
  arm_cortex-a7_neon-vfpv4  armv7-unknown-linux-musleabihf     -C target-cpu=cortex-a7
  arm_cortex-a7             armv7-unknown-linux-musleabi       none
  arm_cortex-a15_neon-vfpv4 armv7-unknown-linux-musleabihf     -C target-cpu=cortex-a15

Point CC_<target>, AR_<target> and CARGO_TARGET_<TARGET>_LINKER at the
cross gcc and ar of the SDK toolchain, for example:
  export CC_armv7_unknown_linux_musleabihf=$TC/bin/arm-openwrt-linux-gcc
  export AR_armv7_unknown_linux_musleabihf=$TC/bin/arm-openwrt-linux-ar
  export CARGO_TARGET_ARMV7_UNKNOWN_LINUX_MUSLEABIHF_LINKER=$TC/bin/arm-openwrt-linux-gcc
  export RUSTFLAGS="-C target-feature=-crt-static <extra>"
  cd rust
  cargo +nightly build --release --target <target> \
    -Z build-std=std,panic_abort --target-dir target-<arch>

arm_fa526 has no built-in musl target. Use a custom target spec file
named armv4t-unknown-linux-musleabi.json (ARMv4T, soft-float, musl,
dynamic linking, +soft-float,+strict-align) and pass its path as --target
together with -Z json-target-spec. readelf -A must report Tag_CPU_arch
v4T and no ARMv5+ instructions may be present.

mips_mips32 must not contain MIPS32r2 instructions, because the bmips
kernel is built for MIPS32 release 1. -C target-feature=-mips32r2 removes
the r2 features of the default mips-unknown-linux-musl target; readelf -h
must report "mips32" (not "mips32r2"). mips64 uses the built-in
mips64-openwrt-linux-musl target, which is already MIPS64r2 and n64 ABI.

Copy the resulting binaries to the matching files* tree.
The package Makefile selects the files* tree automatically from
ARCH_PACKAGES (the package architecture). The same aarch64 binaries are used for
aarch64_generic, aarch64_cortex-a53, aarch64_cortex-a72 and
aarch64_cortex-a76; the same mipsel binaries are used for mipsel_24kc and
mipsel_74kc. Every other package architecture, including x86_64 and
riscv64_generic, has its own files* tree; 25.12.6 uses the -25.12
variants.

OpenWrt packages
----------------
Put package/zapret2 and package/luci-app-zapret2 into the SDK package/
directory, then build:

  24.10.5:
    make package/zapret2/compile package/luci-app-zapret2/compile

  25.12.6, native APK:
    make package/zapret2/compile package/luci-app-zapret2/compile

  25.12.6, optional IPK:
    make CONFIG_USE_APK= package/zapret2/compile package/luci-app-zapret2/compile

The package Makefile downloads upstream zapret2 v1.0.2 source and builds
nfqws2 and mdig for the target. Package versioning is independent:
all packages use project version 1.0.0-r1.

The LuaJIT dependency requires host GCC multilib when building for 32-bit
targets. If the default host GCC lacks 32-bit libgcc, select a multilib
compiler explicitly, for example: make HOSTCC=gcc-15 ...

Installer
---------
install-zapret2.sh installs the published packages on a running OpenWrt
system. It detects the package manager and architecture, selects the
matching release archive, installs zapret2 and, when LuCI is present,
luci-app-zapret2. It can also offer to install the Russian LuCI language
packages. On OpenWrt 25.12.6 it installs the APK signing key into
/etc/apk/keys/ and verifies package signatures.

Usage examples:
  wget -qO- https://raw.githubusercontent.com/alex0310/zapret2-openwrt/main/install-zapret2.sh | sh
  wget -qO- .../install-zapret2.sh | sh -s -- --start
  wget -qO- .../install-zapret2.sh | sh -s -- --no-luci --yes
  wget -qO- .../install-zapret2.sh | sh -s -- --lang-ru
  sh install-zapret2.sh 1.0.0-r1 --dry-run

The installer targets OpenWrt 24.10.5 (IPK) and 25.12.6 (APK), and the
mipsel_24kc, mipsel_74kc, mips_24kc, mips_mips32, mips64_octeonplus,
arm_xscale, arm_fa526, arm_cortex-a9, arm_cortex-a9_neon,
arm_cortex-a9_vfpv3-d16, arm_cortex-a7, arm_cortex-a7_vfpv4,
arm_cortex-a7_neon-vfpv4, arm_cortex-a8_vfpv3,
arm_cortex-a15_neon-vfpv4, aarch64_generic, aarch64_cortex-a53,
aarch64_cortex-a72, aarch64_cortex-a76 and x86_64 package architectures,
plus riscv64_generic on 25.12.6 (RISC-V is not
supported on 24.10.5 because its feeds have no LuaJIT for RISC-V). On
other 24.10.x or 25.12.x releases it prints a warning, recommends the
tested release, and waits for Enter before continuing. Use
--allow-unsupported for non-interactive runs. It does not install
sysupgrade images.

APK signing
-----------
The 25.12.6 APK packages are signed with the project key. The public key
is published in apk-keys/zapret2-apk-key.pem and as a release asset with
the same name. To install packages manually with signature verification,
copy it to /etc/apk/keys/ on the router:

  wget -O /etc/apk/keys/zapret2-apk-key.pem \
    https://github.com/alex0310/zapret2-openwrt/releases/download/v1.0.0-r1/zapret2-apk-key.pem

OpenWrt SDKs produce unsigned APK files (only feed indexes are signed),
so release packages are re-signed after the build:

  apk adbsign --allow-untrusted --keys-dir <dir-with-public-key> \
    --sign-key private-key.pem zapret2-1.0.0-r1.apk
  apk verify --keys-dir <dir-with-public-key> zapret2-1.0.0-r1.apk

The private key is not part of this repository. install-zapret2.sh
installs the public key automatically and then runs apk without
--allow-untrusted. If the key cannot be downloaded, the installer falls
back to --allow-untrusted.
